## Verified local fixes - not deployed

**Bound ranking percentile work to candidates.** The endpoint previously calculated five percentile ranks for every member of the 5,000-stock reference cohort, even when only a bounded candidate set could be returned. It also loaded fresh full-market compressed histories for fallback targets. It now retains the full reference distributions, computes percentiles only for candidates, and filters fallback history queries by candidate exchange/symbol. Fixed denominator, tie behavior, eligibility and selected-stock fallback remain covered by regression.

An isolated synthetic 5,000-member / one-candidate benchmark changed **25,000 percentile calls / 18.9608 seconds** to **five calls / 0.0278 seconds**, retaining RS **50.02** and a complete 5,000-member reference cohort. This is a local CPU-path benchmark, not production latency or proof of the observed HTTP failures' cause. [Before](deployment-verification-2026-10-15/local-ranking-before.json), [after](deployment-verification-2026-10-15/local-ranking-after.json).

**Use one final decimal HALF_UP rounding policy.** Recomputing four captured rows in the old frontend differed from the API by one cent at half-cent boundaries: FSLR 28.56/28.57, LI 21.47/21.48, HUHTAMAKI 15.34/15.35, GENCON 7.73/7.74. Server and client now round the final weighted sum once using decimal half-up arithmetic, shared by dashboard and ranking calculations. Weights, component values, coverage and missing-data rules are unchanged. Exact half-cent API values previously rounded downward may increase one cent: **10 of the 400 captured rows** differ under the explicit new policy. Existing immutable snapshots are not rewritten. [Cross-language replay](deployment-verification-2026-10-15/local-rounding-parity.json) finds **zero server/client mismatches across all 400 rows** and lists every API rounding change.

Current validation: **56 backend tests, five Node scoring tests, 113 API replay checks**, independent EMA/RSI/ROC/Bollinger calculations for five stocks x three timeframes, frontend build and lint pass. **184 browser checks / 110 layout cases** also pass, with zero console/runtime or measured layout failures across AAPL, NVDA, LITE, NSE RELIANCE and BSE TCS at 390/1440 pixels. This is the local built frontend with API responses replayed from recorded real histories, not a production-frontend browser audit. Mobile settings screenshot was visually inspected. Lint retains eight existing warnings; the existing bundle-size warning remains. API/indicator replay uses recorded October 14 real provider inputs; it is separate from the live production observation window. Synthetic values are confined to isolated unit/performance tests.

No production fix for the HTTP failures is claimed. Deploying the local patch or changing production settings requires user approval; neither was performed. Missing external data must remain N/A. Private-log-dependent causes remain BLOCKED without asking for another connection.
